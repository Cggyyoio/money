# MoneyFlow Manager

تطبيق ويب لإدارة الأموال الشخصية وأموال العمل: محافظ، عمليات بعمولات، مصاريف، ديون، تسويات، عملات، تقارير ورسوم، أهداف، وصافي الثروة.
يعمل **بالكامل داخل المتصفح** (بدون خادم ولا قاعدة بيانات خارجية)، فيصلح للرفع مباشرة على **GitHub Pages**.

## الرفع على GitHub Pages
1. أنشئ مستودعًا جديدًا على GitHub وارفع **محتويات هذا المجلد** كما هي (الملف `index.html` في الجذر، ومعه `.nojekyll`).
2. من **Settings ← Pages**: اختر `Deploy from a branch`، الفرع `main`، المجلد `/ (root)`، ثم Save.
3. بعد دقيقة يظهر الرابط `https://USERNAME.github.io/REPO/`. افتحه من الموبايل واختر "إضافة إلى الشاشة الرئيسية" ليعمل كتطبيق (وبدون إنترنت).

لا يوجد أي build ولا npm: الملفات تُخدَّم كما هي. استخدم مستودعًا **Private** لو تريد إخفاء الكود (الصفحة نفسها تبقى عامة، وبياناتك لا تُرفع أبدًا لأنها على جهازك).

## أهم ما يجب معرفته
- **البيانات محفوظة على جهازك فقط** (IndexedDB). لا تُرفع لأي مكان، ولا تظهر على جهاز آخر تلقائيًا.
  خُد نسخة احتياطية من الإعدادات بانتظام (الاسترداد من ملف يعمل على أي جهاز). التطبيق ينبّهك لو مرّ أسبوع بدون نسخة.
- كلمة السر والـPIN **يقفلان الواجهة** ولا يشفّران بيانات المتصفح. النسخة الاحتياطية المشفرة (AES-256-GCM) اختيارية.
- لا يوجد 2FA ولا تسجيل أجهزة ولا CSRF/SQL injection لأنه لا يوجد خادم أصلًا. الحماية من XSS: كل النصوص تُعرض كنص فقط + سياسة CSP صارمة.

## مبدأ الحسابات
- كل الأرصدة = مجموع حركات **الدفتر (Ledger)**؛ لا يوجد رصيد يُعدَّل يدويًا. الدفتر وسجل العمليات وسجل التدقيق وأسعار الصرف **إضافة فقط** (لا تعديل ولا حذف).
- الإلغاء والاسترداد والتعديل = قيود عكسية. الإلغاء/التعديل يعكس الأثر في تاريخ العملية الأصلي، والاسترداد يُسجَّل بتاريخ اليوم.
- ربح العملية = ما دفعه العميل − القيمة. عمولة الشركة = ما خصمته الشركة − القيمة. الصافي = ما دفعه العميل − ما خصمته الشركة.
- التحويل بين محافظك لا يظهر في الأرباح أو المصاريف أو الدخل. التحويل بين عملتين تتحول فروقه إلى بند "إعادة التقييم وتكلفة التحويل".
- كل قيد يحفظ سعر الصرف وقته؛ تغيير السعر لا يغيّر الماضي، لكنه يغيّر تقييم الأرصدة الحالية.
- **فحص السلامة** (الإعدادات) يعيد حساب كل شيء من الدفتر ويقارنه بالأرصدة والتقارير وسلسلة التدقيق.

## ملاحظة على مثال المواصفات
55,000 + ربح 20 − مصروف 150 = **54,870** (وليس 54,850). التطبيق يحسبها صحيحة ويُظهرها كذلك.

## التطوير والاختبار
```bash
npm test                       # 32 اختبار منطق مالي (Node 22، بدون أي حزم)
node tools/serve.mjs 8080      # خادم محلي للتجربة
python3 tests/e2e/run.py       # اختبار شامل في Chromium (يحتاج playwright)
```
الهيكل: `js/domain` (المنطق المالي النقي) ← `js/data` (تخزين، نسخ احتياطي، تصدير) ← `js/ui` (الواجهة). التصميم الكامل في `docs/DESIGN.md` (وُضع قبل التحويل لتطبيق بدون خادم).
